Virux-AUv3 Release Notes

Versions 0.1.129 – 0.1.130

v0.1.130 2026-11-16

  • Editor: the refreshed interface now offers five dark color schemes under Help > Color scheme...: Purple (the default), Blue, Teal, Amber and Neutral. Your choice applies to the current window at once, including the margins around the editor, and new windows open in the same scheme in every plugin format and in the standalone app. The scheme is your own preference and is not saved with songs, so loading a song keeps the colors you picked. Classic Mode keeps its original colors. If Virux cannot save the preference, the window still changes and the display says the choice could not be saved.
  • VST3: notes your host marks as played live now go out on their own queue. They no longer wait behind notes the host has already queued ahead on other keys, and each key's note-on and note-off stay in order. A live note that would collide with a queued note-off on the same key stays in normal order. Hosts that do not mark live notes keep the usual timing, and AUv3 timing is unchanged.
  • Timing: a new option, Help > Even rhythm for live notes (+128 frames), adds a small fixed delay to live notes so they can land more evenly. It is off by default and takes effect within a second of switching it.
  • Timing: DAW count-ins now drive the synth's arpeggiator and LFO clock. Previously the clock stayed silent until the song position passed zero. When you start playback or jump to a new position, the position and start are now sent together with the next clock tick, and small rounding differences from the host no longer restart the clock. Crossing zero at the end of a count-in continues smoothly.
  • Windows: the VST3 now follows your host's actual buffer size for the synth's audio return, including very small 32 and 64 frame buffers, as on macOS. The latency reported to your host now matches the buffering actually used, including when the sample rate is converted. On Linux the latency follows the block size configured in your host.
  • Audio: Virux now watches the synth's audio return for signs that the audio stream has slipped out of alignment, which sounds like loud digital noise. If this shows up for a full second while audio is playing, Virux restarts audio capture once, without reconnecting the synth or interrupting MIDI. Silence and normal loud material do not trigger it, and it happens at most once each time the plugin is activated.
  • Diagnostics: local diagnostic logging is now on by default, so a problem is already recorded when you need to report it. Nothing is uploaded. The log is limited to a 4 MiB file plus one older copy and now rolls over while you work, not only at startup. If you had turned the detailed log off, it stays off, and you can turn it off at any time in Help > Detailed log from next start. The welcome page explains this. Saved diagnostic captures now include the older log copy and note when your host asked for audio before the synth supplied it. On Windows the log now stays within its size limit, and on Linux the log, the USB capture and the saved diagnostics now use the same folder even when no temporary folder is set.
  • Patch sync: the sync progress now shows the name of the last patch received, how many slots are still missing in the current bank and roughly how long that bank will take, not counting pauses while you play. Slots the synth did not answer are no longer counted as read, so the progress bar now reflects patches actually received. A bank that has finished reading is kept even if you cancel right after it.
  • Snow: on a Virus TI Snow, the part meters now follow the MIDI you play on each part instead of the combined level of the synth's audio return, which made all parts move together. Each of the Snow's four parts also shows an activity dot.
  • Help: the Help menu now lists the Access Reference, Quickstart, Atomizer, Virus Control Tutorial and Programming Analogue Synths PDFs when the Access documentation is installed on your computer, and opens them directly. On a Snow, the Snow manuals are preferred, with the Virus TI manuals as a fallback. No Access manuals come with Virux; if none are found, the menu reminds you to install your Access documentation.
  • AUv3: selecting a patch and editing in the editor now reach the synth in the order you made them. Previously the bank select, program change, patch transfer and following edits could overtake each other, especially while a patch sync was running, so the synth could end up on the wrong patch or miss edits. Commands for one synth no longer hold up another synth.
  • AUv3: patch sync in the AUv3 editor now behaves like the standalone app. If the synth was not ready to send its RAM banks, saved ROM banks no longer count as a finished sync, and Virux tries again on its own. The long ROM download no longer starts when the RAM read failed, and a retry reuses RAM banks already read.
  • MIDI recovery: in the plugins, when the synth stops accepting MIDI and Virux tries its second MIDI route but the synth is busy or still settling, Virux now waits and tries that route again every five seconds, even if you play nothing. Previously this could be treated as a failure and show the 'synth stopped accepting MIDI' notice too early. If MIDI starts working again in the meantime, the retry is cancelled, and a route that actually failed is still not retried.
  • Testing: new coverage for the color schemes, including readable text on every surface in each scheme, saving and restoring the choice, damaged preferences, songs that must not change the scheme and Classic Mode staying unchanged. Live notes are tested to bypass queued notes without ever reversing note-on and note-off, the even-rhythm delay at common sample rates, count-ins and crossing zero without a clock restart, slipped-audio detection that ignores silence, music and noise and restarts capture only once, log size limits while running, sync progress that counts only received patches, AUv3 editor commands staying in order, and the MIDI route retry for every busy or settling case.

Virux-AUv3 Release Notes

Versions 0.1.107 – 0.1.108

v0.1.108 2026-10-07

  • Bank editing: drag a patch into the other browser pane to copy it. Dropping on an existing patch replaces that slot; dropping on free space appends at the first unused program number. Sorting and filtering do not change the destination slot, a floating label identifies the patch being copied, the source stays intact, and program numbers and SysEx checksums are repaired on copy (GitHub issue #6).
  • Bank editing: right-click a browser, or open its bank selector or Export menu, for the new Edit / save bank... actions. New empty bank... creates a named blank bank, Duplicate bank for editing copies a library or device bank into an editable draft, Clear bank... asks before removing all patches from a file or draft bank, and Undo last bank edit reverses the most recent copy, replacement, append or clear.
  • Bank editing: Append current edited patch adds the focused part's loaded patch to the bank, including its current editor parameter values, without a device read. Save bank as MIDI... writes the displayed bank to a .mid file; empty banks round-trip through save, import and folder scanning. This is separate from the existing .vtibackup device-cache export.
  • Bank editing: an asterisk marks a working draft bank. Edits survive bank rescans, device-cache refreshes, editor close/reopen and DAW project saves, and files change only through an explicit save dialog; Clear never erases a file. Banks hold up to 128 patches with up to 128 simultaneous drafts. Device RAM/ROM banks serve as copy sources; drag and drop does not write hardware bank memory.
  • HW Link/USB: a field report showed a refused USB session being treated as open, enabling MIDI fallback and repeating arm attempts against an unresponsive device. A failed session opener or restore now latches the device handle as failed: HW Link and external MIDI forwarding are disabled, host MIDI is gated, further sync/link/fallback openers on that handle are refused, and the per-synth cooldown is recorded. The post-sync MIDI path now requires a completed opener, completed restore and running pump on every model.
  • Patch sync: all three background agents now stop automatic sync attempts after a USB transport failure until the synth is observed to disconnect and return. A failed RAM sync no longer proceeds to open a ROM session, while busy, cancellation and cooldown states remain retryable. A device whose USB engine is already wedged may need a full power cycle after updating both the plugin and the background service.
  • Testing: replays of both field-captured opener failures (ten failing assertions before the fix), the full post-sync routing decision matrix, 500 agent retry ticks at the observed cadence, and broad bank-editing coverage including filtered destinations, undo, MIDI round trips, same-name files in separate folders and malformed state rejection. 78/78 CTest cases and 47/47 VST3 validator checks passed on Windows.
